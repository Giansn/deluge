8. Tools for the computer

Three small Windows programs record the Deluge, retune a sample library and even out the levels of a card. Two browser pages log the CPU monitor and the profiler, and two web apps reach the SD card over USB.

8.1 Overview

  • As Python scripts they are in mastertune-1.2.1/tools/.
  • All three have the Deluge's look, and each button shows its keyboard key below it. DelugeTuner and DelugeBaseline switch between German and English (SPRACHE / LANGUAGE).

8.2 DelugeRec

DelugeRec records the "Deluge" input from USB audio (chapter 4) bit-exact as a 24-bit WAV file. On Windows it uses WASAPI exclusive mode, and the display shows whether 24 bits really arrive. It only listens: it sends nothing to the Deluge.

ControlWhat it does
RECStarts recording.
ARMStarts as soon as the signal exceeds a threshold (THRESH), with 0.3 s of pre-roll.
STOPEnds the take.
MONThe monitor on the headphones.
OUTChooses the monitor's output: up/down, mouse wheel or the knob, then Enter. The Deluge itself is never offered.
FOLDEROpens the folder with the recordings.
VOLLeave it at 0 dB: then the recording is bit-exact. Turning it down doesn't repair clipping that already happens in the Deluge.
PadsThe level. For the baseline in §5.8 the pad at −3 should stay dark.
  • Take names: with firmware v18 or later, DelugeRec names each take after the song, the date and the firmware, for example "Song name, 28.09.2026 - 1.2.1 v18.3.WAV". The Deluge reports the song name while the audio stream is open (§4.5). From v18.2 on you need DelugeRec v7: v6 cuts the version off at the dot.
  • As a script: pip install sounddevice numpy, then python tools/deluge_rec.py. Without a Deluge: --demo.

8.3 DelugeTuner

Away from 440 Hz the Deluge resamples every sample voice (§2.5). DelugeTuner converts the sample library of a card once to the master tune. The converted files carry the mtun chunk (§2.3), so the Deluge plays them directly again. The firmware needs no change for this.

  1. CARD: choose the SD card or a copy of it. It is only read.
  2. OUTPUT: choose a folder on the computer for the new card. An empty folder becomes the new card; otherwise a new folder "Deluge 432 Hz" is created inside it, numbered if needed. A folder inside the card is refused.
  3. Gold knob: the tuning, 415.3 to 466.2 Hz, 432 Hz at the start. Drag, the mouse wheel or + and − change it by 1 Hz; with Shift or the arrow keys left and right by 0.1 Hz. Click the number to type it.
  4. Checkboxes: 44.1 kHz or each file's own rate; peaks above 0 dBFS as 32-bit float or a little quieter.
  5. MODE: READ only shows what it would do, RETUNE writes the new card. Press START; display and pads show the progress, then the summary. REPORT opens RETUNE_REPORT.txt (in English).
  6. Copy the new card to an empty SD card and set the same master tune on the Deluge.

Beforehand it checks the free space at the output folder: about 5% more than the card. ESC or closing the window stops as soon as the files in progress are finished. START with the same card, output folder and settings continues where it stopped.

What it does to the card:

  • Resamples every sample at the exact ratio (440/432 = 55/54): a 440 Hz tone then measures 432.00 Hz, and the file gets 55/54 longer. 48 and 96 kHz files become 44.1 kHz in the same pass.
  • Adjusts start and end markers, loops and audio clip positions in all songs, kits and synths, and the smpl and cue chunks in the files.
  • Gives time-stretched audio clips and samples a _ts copy that only shifts the pitch and keeps the length. AIFF files become WAV, because the Deluge reads mtun only in WAV.
  • Clips nothing: a file whose peaks would go above 0 dBFS is written as 32-bit float, or made just as much quieter as needed. The Deluge limits float samples to 0 dBFS when it loads them. The report lists these files.
  • Never changes the original card. A second run changes nothing more. Wavetables, files that already carry the target tuning and files the Deluge can't read stay as they are.

What it gains (emulator, 432 Hz): every untransposed voice plays directly. Per voice and block the work drops from 13,300 to 2,490 instructions (mono) and from 19,800 to 3,000 (audio clip). The whole test card needed 34% less without the sample cache, 6% less with it.

  • Always the whole card: convert a copy of the whole card and copy the whole result to a second card, never single folders. Otherwise samples that several songs share would be converted, but the positions in the other songs would not.
  • Transposed notes are still resampled, for example a synth sample played melodically. At 440 Hz the converted samples sound right thanks to mtun, but cost resampling again.
  • Very short loops and single-cycle samples can be detuned by up to 1.4 cents, because loop lengths are rounded to whole samples. The tool warns about this. In _ts copies attacks can shift by up to 4.6 ms.
  • Loops that no song uses are treated like single samples. If you later make an audio clip from one, the Deluge stretches it again. Take such loops from a copy of the originals.
  • Converted cards have not been played on a real Deluge yet.

Command line: pip install numpy soxr pylibrb, then python3 tools/retune_library.py --card CARD_COPY --out NEW_CARD (default 432 Hz, 44.1 kHz). --dry-run only shows, --resume continues after an interruption, --no-float makes peaks quieter instead of writing float.

8.4 DelugeBaseline

DelugeBaseline checks all songs on a card against the level baseline in §5.8 and can set them to it. It has two functions, each in the mode READ (only shows) or APPLY (shows, then writes on the second START):

FunctionWhat APPLY changes
LEVELSSong volume above 35 to 35, master compressor off. Kits and audio tracks above 35 to 35. Synths and kit rows down far enough that they act at most like 40 with a fully driven sample. Automation keeps its shape. Saturation, the tracks' compressors, analog delay and filters stay: that is sound, not level.
NORMRaises every sample under SAMPLES/ whose peak lies below the target (TARGET knob, default −1 dBFS) up to the target, never above. Nothing clips; format, bit depth and chunks stay. With COMPENSATE (on by default) every oscillator that plays a raised sample is turned down by exactly as much, in every song, kit and synth, so the songs sound as before. Wavetables and audio clips are never touched.
  • Buttons: FUNCTION LEVELS (L) or NORM (N), MODE READ (R) or APPLY (A), START (Enter), CARD (C), REPORT (T) opens the whole report as text, RESTORE (B) shows the backups.
  • APPLY first shows what would change, and the pads of the songs concerned blink. START again writes, Esc cancels.
  • WRITE TO: SD CARD DIRECTLY, with the old files in BASELINE-BACKUP/, or COPY FOLDER, with only the changed files in the card's layout. RESTORE plays a backup back.
  • The report lists songs, kits or audio tracks above 35, a master compressor that is on, synths and kit rows above 40 (marked "no notes" if the row has no notes), and stages that distort more with level: saturation, compressor, analog delay with feedback, low-pass with drive, filters with resonance from 25. Every level is shown as the value and in dB as on the Deluge, for example "40.0 (+8.16 dB)".
  • Its limit: it doesn't tell you whether a song clips. Only measuring shows that, for example with DelugeRec.

Without a window: py tools/deluge_baseline.py [--lang en] check|levels|normalize E:\ [--yes]. Without --yes it only shows what it would do.

8.5 The CPU monitor page

  1. Connect the Deluge by USB and switch the CPU monitor on (§3.4).
  2. Open tools/cpu_monitor.html in Chrome or Edge; dragging the file into the window is enough. Click Connect and allow MIDI with SysEx.
  3. Leave the input on "All inputs" or choose the Deluge's port 3. Tiles and a graph of the last 5 minutes run live.
  4. Export CSV saves every second received: one line per second, semicolon as separator.
ValueMeaning
CPU meanComputing time of the audio routine divided by the duration of the audio it produced. Above about 90% all the time, it gets tight.
CPU peakThe most expensive single pass. Single peaks above 100% are absorbed by the output buffer (128 samples, 2.9 ms).
VoicesActive voices, now and the maximum.
Direness0–14. Above 0 the audio routine is behind the output and the quality is lowered (QL). The share says how much of the audio was made that way.
CullingVoices per second that the CPU protection really fades or switches off (VC). Voice stealing because of the polyphony doesn't count.
SD cardPure read time of a sample cluster, mean and longest. It shows how fast the card is.
SD latency incl. audioThe same accesses from start to end, including the audio computed meanwhile: how long streaming waits for a cluster. If it is much bigger than the card time, the CPU slows streaming down, not the card.
Longest audio gapThe longest interval between two passes of the audio routine. From about 2.9 ms on, dropouts threaten.

8.6 The profiler

With Settings → CPU monitor → Profile the Deluge shows the usual line and also sends, 1000 times a second, where in its code it is working, plus the exact CPU time of each track. v16 It costs about 0.04% CPU and about 8 KB/s on USB MIDI port 3; the buffer always leaves 1 KB free, so notes and clock don't wait.

  1. Open tools/profiler.html in Chrome or Edge and click Connect.
  2. Load symbols: choose the .symbols.json next to the firmware you installed. Only the matching file gives the right function names.
  3. Set the Deluge to Profile and play. Reset separates two parts, for example idle and playing.
  4. Read the tables by track, by task and by function, or Save recording as a .jsonl file.

While a track computes, interrupts are off. That time shows up collected as Song::renderAudio; which track it was is under "by track".

Without a browser, tools/deluge_profiler.py does the same (pip install mido python-rtmidi; on Windows use Python 3.12). ports lists the Deluge's three ports, live prints one line per second, record -s 60 -o profile.jsonl records, report profile.jsonl --symbols FILE evaluates. It finds port 3 by itself. The live line:

CPU 43.0 % (peak 71.0) voices 24 (max 30) QL 0 (0.0 % of the time) cut 0 gap 3.1 ms SD 11 loads, avg 1.7 max 9.0 ms

PartMeaning
CPULoad of the audio windows: mean and peak of the last second. From v17 on this is the real load; up to v16 an idle Deluge showed 85–90% of busy waiting.
voicesSounding voices, now and the maximum.
QLQuality lowered: the direness (0–14) and for how much of the time.
cutVoices cut by the CPU protection. The number that counts.
gapThe longest pause between two runs of the audio routine. From about 2.9 ms on a dropout threatens.
SDLoads from the card, mean and longest duration.

With Profile, live adds every 5 s the audio routine's share, the most expensive tracks and tasks and, with --symbols, functions.

8.7 The SD card over USB: DEx and deluge-editor v7

The card stays in the Deluge. Connect the Deluge by USB, open the web app in Chrome, Edge or Opera and allow MIDI access. The apps find the file access by themselves.

AppWhat works
DEx dex.silicak.esFile browser: view folders, upload and download files, rename, copy, move, delete, create folders. As before also display mirroring and screenshots.
deluge-editor cyface.github.io/deluge-editorOpen synth and kit presets directly from the card and save them back.

File access works only over USB; the Deluge ignores such requests on the DIN sockets. Its USB MIDI send buffer is four times as large as in 1.2.1, so even a full folder page with long names fits.

  • deluge-editor shows "needs community 1.3.0 or later" in red, because the Deluge honestly reports 1.2.1. Ignore it: opening and saving work.
  • deluge-editor hides controls it only knows from 1.3 on, among them the arp additions (chapter 6). Set those on the Deluge; they are kept in the file. "Live Edit" doesn't work.
  • Names with umlauts are shown wrongly, and such files usually can't be opened. Use only A–Z, 0–9 and _ in names.
  • During playback don't delete or overwrite samples the song needs. Large transfers are slow over MIDI; for whole sample collections a card reader is faster.
  • Don't transfer files while you play with a DAW over USB: notes and clock to the computer share the send buffer and can arrive late. DIN MIDI is not affected.
