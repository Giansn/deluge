## Warum der Hash die ganze Datei ändert

- CMake schreibt `git rev-parse --short HEAD` in den Versionsstring `1.2.1-mastertune-v16-<hash>` und in `kCommitShort`.
- `handle_cpu_fault()` zeigt bei einem Absturz die ersten 4 Hex-Zeichen des Hashes auf den Pads. LTO rechnet diese Zeichen als Konstanten ein. Mit `0fc5` statt `c610` wird die Funktion 30 Bytes länger, und alles ab `routineForSD` liegt 32 Bytes weiter hinten. Deshalb unterscheiden sich 797'959 Bytes, bei gleicher Dateigrösse.
- Sonst ist nichts eingebettet, weder Build-Pfad noch Datum (mit `strings` geprüft).

## Die Original-Hashes lassen sich nicht nachbauen

- Die `From`-Zeilen der Patches sind die Original-Commits: 0001 = `49e71650`, 0055 = `c610417f`. Die älteren Releases tragen dieselben Namen (v3 `09dcce01` usw.).
- Committer = Autor und Zeit = Autorzeit trifft keinen der 55 Hashes, weder signiert noch unsigniert. Ich habe für 0001 auch Committer-Zeiten von −1 h bis +3 Tage durchsucht, mit zwei Identitäten und zwei Zeitzonen: kein Treffer.
- Vermutlich waren die Commits signiert. Dieser Container signiert jeden Commit per SSH (`commit.gpgsign=true`), dann hängt der Hash an der Signatur und am Schlüssel. Das lässt sich nicht nachbauen.

## Rezept zum Nachbauen

```sh
git clone https://github.com/SynthstromAudible/DelugeFirmware && cd DelugeFirmware
git checkout release_1_2_1 && git config core.abbrev 8
ls /pfad/zu/patches/00*.patch | head -55 | GIT_COMMITTER_NAME=Claude GIT_COMMITTER_EMAIL=noreply@anthropic.com \
  xargs git -c commit.gpgsign=false am --committer-date-is-author-date      # HEAD 0fc5d96e, für alle gleich
./dbt configure -DRELEASE_TYPE:STRING=mastertune-v16                         # hier dazu -DFETCHCONTENT_SOURCE_DIR_ARGON=…
# in build/src/deluge/version/version.cmake den execute_process mit "rev-parse --short HEAD"
# durch  set(GIT_COMMIT_SHORT "c610417f")  ersetzen
./dbt build release                                                          # 7eed1a77… = v16
```

## Vorschlag

Wenn künftige Releases ohne Eingriff aus den Patches nachbaubar sein sollen, gibt es zwei Wege:

- **Deterministische Kette:** Vor dem Release-Build die Kette wie oben neu aufbauen, also unsigniert und mit Committer-Zeit = Autorzeit, und daraus bauen. Dann ergibt der Befehl bei allen denselben Hash und dieselbe Datei.
- **Hash fest vorgeben:** eine CMake-Variable, die `GIT_COMMIT_SHORT` überschreibt, und der Wert im README.
