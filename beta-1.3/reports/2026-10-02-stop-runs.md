# Stop runs: is the beta stable? (02.10.2026)

The criterion for "stable" is a stop run that finds no problem on the build with all patches. A stop run is 2 hours of `tests/fuzz_ui.py --mode deep`, two seeds at a time (OLED and 7-segment), 20 minutes per seed. Half of its inputs are two-finger combinations. Every problem is replayed, its root cause found, and then it is fixed, or shown to be a fuzzer artefact, before the next run. The dev session adds patches at the same time (0017-0020 during these runs), so a run that would end on an older series is stopped and started again on the whole one.

A problem counts if it is any of these:
- a crash, a freeze (E/i codes), a fault handler or a hang;
- an access outside RAM and the peripherals;
- a write through a null pointer;
- an error popup that the card doesn't explain.

Between the runs, two code reviews looked for more faults of the kinds already found:

## Expected popups

The test card has song files and five synth presets, but no kits and no MIDI definitions. So these popups come from the card, not from the firmware:
- **Error 10:** no KITS folder. The fuzzer leaves these out.
- **Error 16:** no further files, when a kit row is created.
- **Error 2:** the MIDI instrument browser has no file selected (`load_instrument_preset_ui.cpp:268`, `:1128`).
- **Error 15** (preset in use, seed 160): on an audition pad, like the browser's other errors. The card has only five synth presets. Not traced.

## What this covers, and what it doesn't

- **Emulator only:** the firmware of the Deluge runs as it is, with the card, the audio and the displays modelled. Nothing here has run on a Deluge.
- **The fuzzer's reach:** random input finds a lot, but not everything. The runs reached the arranger's automation view, the grid layout, song loads, the audio recorder and the browsers. Long sessions, MIDI and USB input, and files from other firmwares are not covered.
- **1.2.1:** mastertune shares 0108's path and 0110's audio and MIDI cases (NIGHTLY.md section 7).
