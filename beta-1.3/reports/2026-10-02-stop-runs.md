# Stop runs: is the beta stable? (02.10.2026)

"Stable" means a stop run that finds no problem on the build with all patches: 2 hours of `tests/fuzz_ui.py --mode deep`, OLED and 7-segment in parallel, 20 minutes per seed, half of the inputs two-finger combinations. Every problem is replayed, root-caused, and fixed or shown to be a fuzzer artefact before the next run. The dev session adds patches meanwhile (0017-0024), so a run that would end on an older series is stopped and restarted on the whole one.

A problem counts if it is any of these:
- a crash, a freeze (E/i codes), a fault handler or a hang;
- an access outside RAM and the peripherals;
- a write through a null pointer;
- an error popup that the card doesn't explain.

## Expected popups

The test card has songs, samples and five synth presets, but no kits and no MIDI definitions, so these popups come from the card:
- **Error 10:** no KITS folder. The fuzzer leaves these out.
- **Error 16:** no further files, when a kit row is created.
- **Error 2:** the MIDI instrument browser has no file selected (`load_instrument_preset_ui.cpp:268`, `:1128`).
- **Error 15** (preset in use, seed 160): the card has only five synth presets. Not traced.
- **Song Chord Memory** (seed 188): a keyboard column's mode popup, not an error; the rig's error words include "memory". The fuzzer now leaves it out.

## What this covers, and what it doesn't

- **Emulator only:** the Deluge's firmware runs as it is, with the card, audio and displays modelled; nothing here ran on a Deluge.
- **The fuzzer's reach:** the runs reached the arranger's automation view, the grid layout, song loads, the audio recorder and the browsers. Long sessions, MIDI and USB input (the dev session's `--midi` rounds cover MIDI), and files from other firmwares are not covered.
- **1.2.1:** mastertune shares 0108's path and 0110's audio and MIDI cases (NIGHTLY.md section 7).
